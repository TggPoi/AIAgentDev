# 战斗系统设计规划文档

## 文档目的

本文档用于定义当前 Agent RAG 测试项目中的战斗系统设计方向，主要面向 **产品规划部门 product_planning** 使用。

该文档用于辅助以下工作：

* 战斗系统需求设计
* 技能机制规划
* 玩家成长节奏规划
* 敌人行为设计
* 关卡战斗体验评估
* 后续开发任务拆分
* 战斗体验测试验收

本文档属于产品规划部门内部知识库内容。非 product_planning 部门用户在权限过滤正确的情况下，不应该检索到本文档内容。

---

## 1. 战斗系统总体目标

本项目的战斗系统目标不是追求复杂操作，而是让玩家在较短时间内理解战斗规则，并通过技能组合、走位、资源管理获得持续成长感。

核心体验目标是：

```text
易上手
有反馈
有节奏
有成长
有策略空间
不依赖过度数值碾压
```

战斗系统需要让玩家明确感受到：

1. 自己为什么打赢。
2. 自己为什么失败。
3. 哪个技能选择产生了作用。
4. 哪个敌人行为需要应对。
5. 下一次战斗可以如何优化。

战斗失败不应让玩家觉得随机或不公平，而应该让玩家意识到：

```text
我可以通过换技能、调整站位、观察敌人前摇、管理资源来打得更好。
```

---

## 2. 核心战斗循环

基础战斗循环如下：

```text
观察敌人动作
    ↓
选择移动或防御
    ↓
寻找输出窗口
    ↓
释放普通攻击或技能
    ↓
积累资源
    ↓
使用关键技能打出爆发
    ↓
处理敌人反击
```

该循环要求敌人动作必须有清晰前摇，玩家技能必须有明确反馈。

如果敌人攻击没有前摇，玩家会认为受伤不公平。

如果玩家技能没有明显命中反馈，玩家会认为技能没有价值。

---

## 3. 玩家基础能力

玩家默认拥有以下基础能力：

| 能力   | 设计目的        |
| ---- | ----------- |
| 普通攻击 | 提供基础输出和资源积累 |
| 闪避   | 提供主动规避能力    |
| 技能 1 | 低成本常用技能     |
| 技能 2 | 中等成本控制或范围技能 |
| 终结技  | 高成本爆发技能     |
| 被动能力 | 强化战斗风格      |
| 战斗道具 | 提供临时策略选择    |

玩家的基础操作不宜过多。

初期版本建议控制在：

```text
移动
普通攻击
闪避
两个主动技能
一个终结技
```

这样可以避免学习成本过高。

---

## 4. 普通攻击设计

普通攻击是战斗中的基础行为。

普通攻击应满足：

* 动作速度稳定
* 命中反馈清楚
* 可用于积累能量
* 可以衔接部分技能
* 不应成为唯一最优输出方式

普通攻击推荐采用三段式设计：

```text
第一段：快速起手
第二段：稳定连击
第三段：较高伤害，但后摇稍长
```

设计目的：

```text
前两段提供安全输出
第三段提供伤害奖励
但第三段也带来风险
```

如果玩家贪第三段攻击，可能被敌人反击。

这可以形成简单但有效的战斗决策。

---

## 5. 闪避设计

闪避是玩家主动规避伤害的核心能力。

闪避需要满足：

* 输入响应及时
* 无敌帧时间适中
* 冷却或体力消耗明确
* 动作结束后有短暂恢复
* 不能无限连续使用

推荐设计：

```text
闪避有短暂无敌帧
闪避消耗耐力
耐力会自动恢复
连续闪避会快速耗尽耐力
```

这样可以避免玩家通过无限闪避破坏战斗节奏。

闪避的主要价值不是让玩家完全无敌，而是让玩家在正确时机规避关键攻击。

---

## 6. 技能系统设计

技能系统应服务于战斗风格构建。

每个技能至少需要定义以下信息：

```text
技能名称
技能类型
冷却时间
资源消耗
伤害倍率
攻击范围
控制效果
释放前摇
释放后摇
是否可被打断
是否可衔接普通攻击
```

技能类型建议分为：

| 类型   | 作用          |
| ---- | ----------- |
| 输出技能 | 提供直接伤害      |
| 控制技能 | 打断、击退、眩晕、减速 |
| 位移技能 | 改变玩家位置      |
| 防御技能 | 护盾、格挡、减伤    |
| 增益技能 | 提升攻击、速度、暴击等 |
| 召唤技能 | 召唤临时单位或机关   |

技能之间需要有明显差异，不能只是不同颜色的伤害按钮。

---

## 7. 技能组合设计

技能组合的目标是让玩家产生“我搭配出了一套打法”的感觉。

示例组合：

```text
减速技能
    ↓
范围伤害技能
    ↓
普通攻击补充能量
    ↓
终结技收尾
```

另一个组合：

```text
位移突进
    ↓
击飞敌人
    ↓
空中追击
    ↓
落地范围攻击
```

技能组合不应只追求最高伤害，也可以围绕：

* 控制
* 生存
* 位移
* 范围清怪
* 单体爆发
* 持续输出
* 召唤物辅助

不同技能组合应该适配不同战斗场景。

---

## 8. 敌人设计原则

敌人设计必须让玩家能够观察和学习。

每种敌人至少需要有：

```text
基础攻击
特殊攻击
移动方式
攻击前摇
攻击后摇
受击反馈
弱点窗口
```

敌人攻击不能完全随机。

合理的敌人行为应该是：

```text
玩家接近
    ↓
敌人准备攻击
    ↓
出现明显前摇
    ↓
玩家可以选择闪避、打断或远离
    ↓
敌人攻击结束后出现短暂破绽
```

这样玩家才能学习敌人模式。

---

## 9. 敌人类型规划

初期版本建议设计以下敌人类型：

| 敌人类型 | 作用            |
| ---- | ------------- |
| 近战小兵 | 训练玩家基础闪避和攻击节奏 |
| 远程小兵 | 迫使玩家移动和优先处理威胁 |
| 盾牌敌人 | 迫使玩家绕后或使用控制技能 |
| 突进敌人 | 训练玩家观察前摇      |
| 精英敌人 | 检验玩家技能组合      |
| Boss | 提供阶段性挑战和机制学习  |

不同敌人之间需要形成组合压力。

例如：

```text
盾牌敌人限制正面输出
远程敌人持续骚扰
突进敌人打乱玩家站位
```

这样战斗会比单一敌人更有策略性。

---

## 10. Boss 战设计

Boss 战不应只是血量更高的普通敌人。

Boss 至少需要包含：

* 阶段变化
* 明确机制
* 可学习攻击模式
* 安全输出窗口
* 特殊惩罚机制
* 视觉和音效强化

Boss 战推荐分为三个阶段：

```text
第一阶段：教学机制
第二阶段：组合机制
第三阶段：压力测试
```

例如：

```text
第一阶段：
Boss 使用单一范围攻击，玩家学习躲避。

第二阶段：
Boss 加入召唤小怪和范围封锁。

第三阶段：
Boss 攻击频率提高，但破绽也更明显。
```

这样玩家会感觉自己是在逐步理解 Boss，而不是单纯拼数值。

---

## 11. 战斗资源设计

战斗资源用于限制技能释放频率，并制造决策。

可选资源包括：

| 资源   | 作用             |
| ---- | -------------- |
| 能量   | 通过攻击积累，用于释放终结技 |
| 耐力   | 用于闪避、防御、冲刺     |
| 魔力   | 用于技能释放         |
| 冷却时间 | 控制技能节奏         |
| 连击点  | 鼓励连续进攻         |

初期版本不建议同时引入太多资源。

推荐方案：

```text
耐力：控制闪避频率
能量：控制终结技释放
技能冷却：控制主动技能节奏
```

这三个资源已经足够支撑基础战斗策略。

---

## 12. 数值设计原则

战斗数值设计应避免极端情况。

需要重点控制：

```text
玩家基础伤害
技能倍率
敌人血量
敌人攻击力
闪避冷却
耐力恢复速度
技能冷却时间
Boss 阶段血量比例
```

数值调整目标：

```text
普通小怪：短时间击败
精英怪：需要使用技能组合
Boss：需要理解机制并持续执行
```

不要让玩家只靠普通攻击就能解决所有战斗。

也不要让玩家必须依赖唯一技能组合才能通关。

---

## 13. 战斗反馈规范

战斗反馈包括：

* 命中特效
* 受击动画
* 音效
* 屏幕震动
* 伤害数字
* 敌人硬直
* 技能释放特效
* UI 能量变化

反馈强度需要分级。

例如：

| 行为      | 反馈强度        |
| ------- | ----------- |
| 普通攻击命中  | 轻反馈         |
| 技能命中    | 中反馈         |
| 暴击      | 强反馈         |
| 终结技命中   | 极强反馈        |
| Boss 破防 | 极强反馈 + 特殊音效 |

如果所有攻击反馈都很强，玩家会失去判断重点。

---

## 14. 战斗节奏控制

战斗节奏需要有起伏。

一场普通战斗不应从头到尾都是高压状态。

推荐节奏：

```text
进入战斗
    ↓
小规模试探
    ↓
敌人组合制造压力
    ↓
玩家使用技能解决关键威胁
    ↓
进入短暂安全窗口
    ↓
下一波压力出现
```

Boss 战也需要节奏变化：

```text
学习阶段
压力阶段
爆发阶段
喘息阶段
最终阶段
```

持续高压会让玩家疲劳，持续低压会让玩家无聊。

## 17. 验收标准

战斗系统初版验收时，需要检查以下问题：

* 玩家是否能理解普通攻击和技能的区别？
* 玩家是否能通过观察敌人前摇做出反应？
* 闪避是否有价值但不会过强？
* 技能是否形成有效组合？
* 战斗失败原因是否清晰？
* Boss 阶段变化是否可感知？
* 敌人组合是否带来策略压力？
* 战斗反馈是否能区分普通攻击、技能、暴击和终结技？
* 数值是否避免单一最优打法？
* RAG 权限测试中，非 product_planning 用户是否无法检索本文档？

---

## 18. 总结

本文档定义了项目战斗系统的产品规划方向。

核心原则是：

> 战斗系统应该让玩家通过观察、选择、执行和复盘获得成长感，而不是只依赖数值碾压或随机结果。

本文档在 ACL 权限测试中应仅对 product_planning 部门用户可见，用于验证部门级知识库权限过滤是否生效。
