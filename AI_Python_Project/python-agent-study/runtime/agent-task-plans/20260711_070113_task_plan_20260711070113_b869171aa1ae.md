根据指定网页内容，关于 RAG 引擎部署模式的核心内容可归纳为以下五点：

1. **两种核心模式**：RAG 引擎提供**无服务器模式**和**Spanner 模式**，用户可根据项目需求在两者间无缝切换，且两种模式的数据严格隔离 [mcp__fetch_result]。
2. **无服务器模式**：最经济实惠且推荐入门使用。采用全代管式自动扩缩，无需管理基础设施，默认使用 RAG 托管式 Vector Search 2.0 处理向量索引与搜索。该模式**不支持 CMEK** [mcp__fetch_result]。
3. **Spanner 模式**：分配专用 Spanner 基础设施，专为需要 CMEK 合规性或专用隔离数据库实例的工作负载设计（未明确选择时的默认模式）。需手动选择性能层级：基础层级（固定低计算，适合实验/小规模数据）或扩缩层级（生产级性能，支持自动扩缩）[mcp__fetch_result]。
4. **数据隔离与切换机制**：切换模式仅改变 API 路由的活跃后端，**不会迁移或删除数据**。资源永久绑定至创建时处于活动状态的模式，切换后非活跃模式下的数据将暂时隐藏但安全保留 [mcp__fetch_result]。
5. **管理与计费差异**：部署模式为项目级设置，可通过 `GetRagEngineConfig` 和 `UpdateRagEngineConfig` API 查看或更改。两种模式在费用结构、扩缩方式、存储隔离性、CMEK 支持及支持的向量数据库类型上存在差异，且数据清理与停止结算的流程因模式而异 [mcp__fetch_result]。
