## 子任务 1 到底解决什么问题

它不负责新增 Memory，也不调用 LLM。它只是解决一个“数据传递”问题：

> 系统已经从 Redis/PostgreSQL 读取了历史对话，但这些历史只在 Query Rewrite 函数内部使用，后面的 Planner 看不到。

### 当前流程

在 `_prepare_initial_state()` 中：

```
读取 Redis 最近对话
+ 读取 PostgreSQL 历史摘要
→ 生成 memory_context
→ 用于 Query Rewrite
→ 得到 rewritten_query
```

然后只把改写结果放进 State：

```
state["query"] = rewrite_result.rewritten_query
```

后面的 Planner 节点只能拿到这个改写后的 query，而且当前明确传入：

```
task_planner.plan(
    query=state["query"],
    history=[],
)
```

所以原始历史在 Rewrite 完成后，就无法继续传给 Planner。

### 子任务 1 要做的事情

最核心的修改可以理解为一行：

```
state["conversation_context_text"] = memory_context.formatted_text
```

这样 State 中同时存在：

```
{
    "query": "根据刚才找到的部署文档创建验收清单",
    "conversation_context_text": """
        用户：帮我查找 RAG 后端部署文档
        助手：找到了 rag-backend-deployment.md
    """
}
```

后面的 Planner 就可以读取：

```
task_planner.plan(
    query=state["query"],
    history=state["conversation_context_text"],
)
```

### 为什么必须经过 LangGraph State

因为读取 Memory 和执行 Planner 不在同一个函数里：

```
RagAgentPipeline._prepare_initial_state()
    │
    │ 读取 Redis/PostgreSQL
    ▼
LangGraph State
    │
    ▼
decide_next_action 节点
    │
    ▼
AgentTaskPlanner
```

`memory_context` 是 `_prepare_initial_state()` 的局部变量。函数执行结束后，后面的节点不能直接访问它。

LangGraph State 就是节点之间传递数据的“任务数据包”。

可以类比为：

```
前台读取历史资料
→ 放进任务文件夹
→ Planner 从任务文件夹读取
```

如果没有放进 State，Planner 只能看到 Rewrite 留下的一句话。

### 为什么不让 Planner 再读一次 Redis

可以，但不合适：

- Planner 会直接依赖 Redis/PostgreSQL。
- 同一次请求可能读取到不同时间点的历史。
- 重复数据库查询。
- Planner 的测试会更复杂。
- 每个需要历史的节点都可能重复实现读取逻辑。

更合理的是：

```
请求开始时读取一次
→ 固定成本次请求的上下文快照
→ 需要的节点选择性读取
```

### 它不代表所有节点都能使用历史

放进 State 只是让数据可以被传递，不代表自动发给所有 LLM。

允许读取：

```
Planner
最终答案生成
```

禁止读取：

```
Prompt Guard
权限判断
文档候选校验
confirm 真实写入
```

必须由具体节点主动读取：

```
conversation_context = state.get("conversation_context_text")
```

### 这个子任务是否需要单独存在

严格来说，不需要。

它本身没有独立的用户功能，只是 Planner 接入历史的技术前置步骤。为了减少任务数量，建议把它合并到原来的子任务 2：

```
### 子任务 1：Planner 接入 Redis 最近对话和 PostgreSQL 摘要

目标：

在 `_prepare_initial_state()` 中读取现有 ConversationMemoryContext，
将受长度限制的上下文写入 LangGraph State，并在
`decide_next_action` 节点传给 AgentTaskPlanner，替换当前固定的
`history=[]`。

验收：

第一轮：
“帮我查找 RAG 后端部署文档”

第二轮：
“根据刚才找到的文档创建验收清单”

第二轮 Planner 能理解“刚才找到的文档”，并生成正确的文档管理计划。
```

所以最简单的总结是：

> 子任务 1 原本只是把已经读取到的会话历史保存进 LangGraph State，供 Planner 使用。它不是独立功能，建议直接合并到“Planner 接入多轮上下文”任务中。
