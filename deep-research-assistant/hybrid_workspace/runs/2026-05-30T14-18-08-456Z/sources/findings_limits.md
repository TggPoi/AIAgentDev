## 限制

1. **限制一：功能相对基础，缺少高级测试特性**。node:test 作为 Node.js 18+ 引入的内置测试运行器，功能设计以保持轻量为核心目标。相比成熟的第三方框架（如 Jest、Mocha），它缺少内置的代码覆盖率报告、快照测试、强大的 mock/stub 支持以及测试并行化的高级配置。对于需要复杂断言或测试隔离的 CLI 项目，可能需要额外依赖其他库来补充这些功能。

2. **限制二：生态系统和社区支持尚在发展中**。node:test 相对较新，社区插件、教程和最佳实践资源不如 Jest 等成熟框架丰富。在小型 CLI 项目中遇到问题时，可参考的解决方案较少。此外，部分 IDE 和 CI 工具对 node:test 的原生支持仍在完善中，可能需要额外配置才能集成到现有工作流。

## 采用建议

对于小型 JavaScript CLI 项目，建议按以下策略采用 node:test：

- **适用场景**：项目测试需求简单（仅需基础断言和异步测试）、希望减少依赖数量、或追求更快的测试启动速度时，node:test 是理想选择。
- **渐进式采用**：可先在新增测试文件中使用 node:test，与现有测试框架并存，逐步迁移而非一次性替换。
- **补充工具链**：如需代码覆盖率，可搭配 c8 等独立工具；需要 mock 功能时可结合 node:vm 模块或第三方 mock 库。
- **版本要求**：确保团队使用 Node.js 18.7+ 版本，并在 package.json 中明确声明引擎要求，避免兼容性问题。
