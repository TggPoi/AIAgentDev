# Node.js 内置测试运行器 node:test 的限制与采用建议

## 主要限制

### 1. 生态系统与插件支持不足
`node:test` 作为较新的内置模块（2022 年 Node.js 18 正式稳定），其生态系统远不如 Jest、Mocha 等成熟框架丰富。缺乏丰富的插件、断言库扩展和第三方集成工具，对于需要复杂测试场景（如快照测试、Mock 高级功能、代码覆盖率可视化）的项目来说，功能较为有限。

### 2. 开发者体验与工具链不完善
相比 Jest 的零配置、自动 Mock、并行测试等开箱即用特性，`node:test` 需要更多手动配置。缺少内置的代码覆盖率报告、测试监听模式、测试文件自动发现等便捷功能，调试和开发效率较低。社区资源和教程也相对较少，学习成本相对较高。

## 采用建议

**建议：谨慎采用，视项目规模而定**

对于**小型 JavaScript CLI 项目**，如果测试需求简单（仅需基础断言和同步/异步测试），`node:test` 可以作为轻量级选择，避免额外依赖。

但如果项目预期会增长或需要以下功能，**建议继续使用 Jest 或 Vitest**：
- 需要丰富的断言库和 Mock 功能
- 需要代码覆盖率报告
- 需要快照测试或 E2E 测试集成
- 团队熟悉现有测试框架生态

**理由**：`node:test` 目前仍处于发展阶段，对于追求开发效率和长期可维护性的小型项目，成熟测试框架的综合成本更低。
