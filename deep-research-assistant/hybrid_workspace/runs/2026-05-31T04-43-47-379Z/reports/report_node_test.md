# Node.js 内置测试运行器 node:test 调研简报

## 概述

Node.js 22+ 内置的 `node:test` 测试运行器为零配置测试提供了新选择。本简报针对小型 JavaScript CLI 项目分析其适用性。

---

## 3 个适用场景

### 1. 快速原型验证与单元测试
在开发 CLI 工具初期，`node:test` 无需安装和配置任何外部测试框架，创建测试文件后运行 `node --test` 即可立即执行。减少项目依赖，保持代码库轻量，适合快速迭代。

### 2. CI/CD 流水线中的自动化测试
作为内置模块，无需在 CI 环境中额外安装测试依赖，减少构建时间和镜像体积。标准化输出格式便于与 CI 工具集成，启动速度快能显著缩短流水线执行时间。

### 3. 函数 Mock 与依赖隔离测试
内置 Mock 机制可轻松模拟文件系统、网络请求等外部依赖，实现单元测试隔离。无需引入 sinon 等第三方 Mock 库即可测试文件处理逻辑或 HTTP 功能。

---

## 2 个主要限制

### 1. 生态系统与插件支持不足
`node:test` 2022 年才正式稳定，生态系统远不如 Jest、Mocha 成熟。缺乏丰富的插件、断言库扩展和第三方集成工具，对于需要快照测试、高级 Mock、覆盖率可视化等复杂场景的项目功能有限。

### 2. 开发者体验与工具链不完善
相比 Jest 的零配置、自动 Mock、并行测试等开箱即用特性，`node:test` 需要更多手动配置。缺少内置覆盖率报告、测试监听模式、测试文件自动发现等便捷功能，社区资源和教程较少。

---

## 采用建议

**建议：谨慎采用，视项目规模而定**

| 项目特征 | 建议 |
|---------|------|
| 测试需求简单（基础断言 + 同步/异步测试） | ✅ 可采用 node:test |
| 预期项目会增长或需要复杂功能 | ⚠️ 建议使用 Jest/Vitest |
| 需要覆盖率报告、快照测试、E2E 集成 | ⚠️ 建议使用 Jest/Vitest |
| 团队熟悉现有测试框架生态 | ⚠️ 建议沿用现有框架 |

**理由**：`node:test` 目前仍处于发展阶段。对于追求开发效率和长期可维护性的小型项目，成熟测试框架（Jest/Vitest）的综合成本更低。仅当项目保持轻量且测试需求简单时，`node:test` 才是合适的零依赖选择。
