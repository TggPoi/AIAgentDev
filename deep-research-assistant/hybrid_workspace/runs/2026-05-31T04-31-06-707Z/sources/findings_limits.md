# Node.js 内置测试运行器 node:test 限制与采用建议

## 主要限制

### 1. 功能相对简单
- 缺少高级测试特性：无内置快照测试、参数化测试支持有限
- 断言库较为基础：仅支持基本断言，缺少丰富的匹配器和自定义断言
- 代码覆盖率需要额外工具（如 c8）配合，非开箱即用

### 2. 生态系统不成熟
- 第三方插件和扩展工具较少，社区资源有限
- IDE 集成和调试支持不如 Jest、Vitest 等成熟方案完善
- CI/CD 报告格式选项有限，自定义报告器需要自行实现

## 采用建议

| 场景 | 建议 |
|------|------|
| 小型 CLI 项目 | ✅ 推荐使用，零依赖、启动快 |
| 简单单元测试 | ✅ 适合，API 简洁易上手 |
| 需要快照/集成测试 | ⚠️ 考虑 Jest 或 Vitest |
| 大型项目/团队 | ⚠️ 评估生态需求和团队熟悉度 |
| 新项目默认选择 | ✅ 可作为轻量级默认方案 |

**总结**：node:test 适合追求零依赖、测试需求简单的小型项目。若需要高级测试功能或成熟生态，建议选用 Jest/Vitest。
